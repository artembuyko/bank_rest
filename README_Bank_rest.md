# Система управления банковскими картами

Описать данный файл по ТЗ

RESTful-сервис для управления банковскими картами с ролевой моделью (администратор / пользователь). Проект реализован на Java 21 + Spring Boot 3 с использованием JWT-аутентификации, миграций Liquibase и контейнеризации через Docker Compose.

<h3> Задачи, решаемые приложением</h3>
  <ul>
    <li>Аутентификация и авторизация с помощью JWT-токенов.</li>
    <li>Управление картами
    (создание, просмотр, блокировка, активация, удаление) – администратор может управлять любыми картами,
    пользователь – только своими.</li>
    <li>Управление пользователями (администратор создаёт, блокирует, активирует, удаляет пользователей)</li>
    <li>Просмотр карт с пагинацией и фильтрацией (пользователь видит только свои, администратор – все)</li>
    <li>Переводы между своими картами с валидацией суммы, проверкой статусов карт и записью транзакций.</li>
    <li>Просмотр баланса конкретной карты</li>
    <li>Маскирование номеров карт при отображении (**** **** **** 1234) для безопасности</li>
  </ul>


<h3> Запуск проекта </h3>
    <ul>
        <li>Клонирование репозитория: git clone https://github.com/artembuyko/bank_rest/tree/main/src/main</li>
        <li>переход в папку: cd bank-rest</li>
        <li>запуск контейнера: sudo docker compose up</li>
        После всех описанных выше действий, проект будет доступен по адресу http://localhost:8081
    </ul>

<h3>Документация OpenApi</h3>
    <ul>
        <li>Swagger UI (интерактивная документация с возможностью тестирования):
         http://localhost:8081/swagger-ui/index.html</li>
        <li>OpenAPI JSON: http://localhost:8081/v3/api-docs</li>
        <li>OpenApi YML: доступен по пути: docs/openapi.yaml</li>
    </ul>

<h3>Нулевой администратор</h3>
<ul>При первом запуске приложения, если в базе данных отсутствуют пользователи, автоматически создаётся учётная запись нулевого администратора с максимальными привилегиями. 
Этот администратор может создавать других администраторов и пользователей, управлять картами и выполнять все операции, доступные роли ADMIN</ul>

<h4>Учетные данные нулевого администратора по умолчанию</h4>
    <ul>
        <li>username: admin</li>
        <li>password: Admin123!</li>
    </ul>

<h4>Использование нулевого администратора</li>
    <ul>
        <li>1.Войдите в систему с учётными данными нулевого администратора через эндпоинт /api/auth/login.</li>
        <li>2.Используйте административные эндпоинты (например, POST /api/admin/users) для создания новых пользователей с нужными ролями (ADMIN или USER).</li>
        <li>3.Рекомендуется после создания хотя бы одного дополнительного администратора ограничить использование нулевого администратора или сменить его пароль.</li>
    </ul>
